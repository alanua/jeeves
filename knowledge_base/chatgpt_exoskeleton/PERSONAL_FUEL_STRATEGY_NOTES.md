# Personal Fuel Strategy Notes

Status: IDEA_BACKLOG
Scope: public-safe working strategy for earning from AI-era changes without starting from generic SaaS

## Core thesis

Do not start by building a generic AI SaaS in a vacuum.

A stronger path is to connect real-world technical work with practical AI-assisted automation.

The defensible advantage is not generic AI access.

The defensible advantage is domain knowledge, real workflows, trust, implementation ability, and the ability to turn messy operational inputs into useful artifacts.

## Avoid first

```text
generic AI SaaS for everyone
prompt-selling business
broad AI courses without distribution
complex product before paid customer evidence
large API spend before a paid use case exists
```

If a feature can be copied in a few days by any vibe-coded competitor, it is not enough of a moat.

## Service-first direction

Start with service-led automation, not SaaS-first.

Candidate direction:

```text
AI-assisted back office and field documentation for construction, electrical, HVAC, renovation, and small technical firms.
```

Pain points:

```text
scattered photos and chats
manual protocols
lost material requests
slow invoices and change orders
manual time tracking
unclear object/job status
plans and PDFs not converted into useful quantities
language and paperwork friction
```

Possible packages:

```text
photo-to-protocol workflow
job-site chat bot
invoice / offer / change-order assistant
material request tracker
plan/takeoff helper
worker time and object status reporting
smart-home setup and support package
```

## Productization rule

```text
manual/assisted service
-> first paid case
-> repeat the same workflow for 2-3 customers
-> extract reusable module
-> only then consider product/SaaS
```

A reusable module should solve a problem that appears in more than one business.

## 30-day plan

```text
Week 1: list 10 real operational pains.
Week 2: choose one pain with visible time or money value.
Week 3: build a manual or semi-automated demo.
Week 4: show it to 2-3 real contacts and ask whether they would pay for setup/support.
```

Do not pitch AI as magic. Pitch less chaos, faster paperwork, and fewer lost hours.

## Relationship to Skeleton/Jeeves

Skeleton can become a repeatable method for building controlled client automations quickly and safely.

Working loop:

```text
real pain
-> bounded task packet
-> safe automation prototype
-> artifact/result
-> human review
-> customer feedback
-> reusable module if repeated
```

Jeeves later becomes a higher-level assistant/runtime, but early income may come from smaller practical automations in real domains.

## Principle

```text
Do not compete with AI.
Do not sell AI as magic.
Use AI as an exoskeleton for real-world technical work.
Earn first from grounded problems that generic AI founders understand poorly.
```
